## 可以做什么

- **一键开赛**：浏览器里配置答题模型与独立裁判，自动发现 CLI 路径，先跑样题，再挑战完整题库。
- **看着模型攻略**：Galgame 风格的标题页、AI 伙伴场景、题目缩略图与答题动画，实时显示耗时、进度和异常数量，支持停止测试。
- **结算与复盘**：百分制成绩、总分、正确率和耗时统计；点击「查看错题」回看未满分题目，异常题可人工补分。
- **排行与图鉴**：前三名擂台、模型历史检索、成绩筛选和赛季排名；题库以卡片展示，可按榜单、作品开发商和年份筛选。
- **完整留档**：保存答卷、评分依据、模型路线与运行事件，支持 CSV / JSON 导出和按现有记录复评。

后端使用 Python 标准库，前端使用原生 HTML、CSS 和 JavaScript；galbench 本身无需安装第三方 Python 运行依赖，也没有 npm 构建步骤。

## 三个榜单

当前主集共 **900 题，合计覆盖 125 部作品**；作品年份按题库元数据覆盖 **2000–2026**。知识与识图涵盖 Key、柚子社、八月社、枕社、FAVORITE、Navel、minori、戏画社等作品。

| 榜单 | 题量 / 作品数 | 考什么 | 怎么评分 |
| --- | --- | --- | --- |
| 🧠 游戏内知识 `text` | 400 题 / 114 部 | 人物与关系、剧情线路、音乐与人物或剧情的联系、世界观设定；以填空或简短直接回答为主 | 固定答案与别名匹配，每题 0 / 1，不调用模型裁判 |
| 🖼️ 角色识图 `vision` | 400 题 / 120 部 | 给出作品名称与单人角色图片，回答角色全名 | 固定角色名与别名匹配，每题 0 / 1，不调用模型裁判 |
| 📖 剧情总结 `story` | 100 题 / 2 部 | 根据给定游戏内文本，整理主要事件、人物关系、因果和情绪变化 | 独立模型裁判或人工复核，按预设评分细则计算 |

剧情总结目前使用《片轮少女》94 段及 *The Question* 6 段既有中文文本，只要求总结片段，不要求猜作品、认角色或推测后续。角色识图目前以单人角色人物像为主，尚未加入剧情 CG 理解题。

### 分数怎么看

- **每榜满分 100**，当前主集各题等权；完整同场三榜相加为「总分王座」，满分 **300**。不同场次的最佳分不会拼成一场总分。
- 总结按**事件覆盖 30、关系与因果 25、忠实度 25、表达 20**评分；无依据补充、关键事实错误、严重超长或大段照抄会影响得分。
- 调用失败、截断、判分失败和待复核会单独标记，仍可查看参考分、已评分覆盖率及分数上下界。人工补分保留原始异常记录。
- 本地演示成绩不进入排行榜。人工补分、未完成或模型身份未知等记录会保留状态标记；不满足排名条件的记录不争夺名次。

当前题库是来源可追溯的公开开发集，尚未完成双人独立审校。比较模型时，请使用相同题库版本，并结合 Harness、模型路线、轮数和裁判配置理解结果。

## 快速开始

### 1. 准备环境

安装 [Python 3.11 或更新版本](https://www.python.org/downloads/)，Windows 安装时勾选 **Add python.exe to PATH**。下载或克隆本仓库，进入包含 `start_galbench.bat` 的项目根目录。

真实评测还需要安装下表中的一种 Harness，并先在对应客户端完成登录、选择模型或配置模型提供商。只想体验界面，可以先用「本地流程演示」，无需 Harness 或模型账户。

### 2. 启动界面

**Windows：双击 [start_galbench.bat](start_galbench.bat)。** 启动器会检查 Python 版本并打开浏览器；测试期间保持启动窗口运行。

也可以在项目根目录打开终端，运行：

```shell
python -m galbench web --open
```

浏览器地址：**http://127.0.0.1:8765**。端口被占用时，可运行 `python -m galbench web --port 8766 --open`。Windows 若只有 `py` 启动器，可将命令开头的 `python` 换为 `py -3`。

### 3. 连接模型，先跑样题

1. 点击「进入攻略大厅」，打开「选手准备室」。
2. 为**答题模型**选择 Harness。CLI 路径会自动识别；未找到时手工填写可执行文件或受支持的 Node 入口完整路径，不填安装文件夹或整条命令。点击「检查 CLI 安装」。
3. 按需填写「模型调用 ID」。**「榜单显示名」只影响显示，不会切换实际模型**；模型提供商与账户配置由 Harness 管理。
4. 参加识图榜时，确认所选模型支持图片并勾选图片输入。ACP 未显式声明图片能力也会按你的确认尝试发送，实际失败会记录到对应题目。
5. 游戏内知识和角色识图无需裁判。若参加总结榜并希望自动评分，启用并单独配置**模型裁判**；不启用时，总结题进入人工复核。
6. 先选择「流程样题 · 5 / 3 / 2」、并发 **1**，点击开始。确认流程正常后，再切换完整的 **400 / 400 / 100** 主集，也可只选择其中一个或两个榜单。

网页默认并发为 2，上限为 16；每题默认超时 600 秒。并发是否合适取决于本机性能、Harness 和账户额度；生成预算与思考设置由 Harness 管理。点击「停止测试」会保留已有结果；服务商已经处理的请求仍可能产生用量。

## 支持的 Harness

真实答题与模型裁判均通过**本地 Agent / Harness CLI**调用，可分别选择不同客户端。galbench 不提供直接填写模型 API 地址和密钥的接入入口；第三方模型在 Harness 自己的提供商设置中配置。

下表列出本项目已实现的适配。点击名称可查看官方项目或文档，按其说明安装与认证。

| Harness | 默认命令 | 接入要点 |
| --- | --- | --- |
| [Codex](https://github.com/openai/codex) | `codex` | 支持模型 ID 覆盖，以及沿用客户端配置和 profile；可传入原生图片 |
| [MiniMax Code](https://github.com/MiniMax-AI/minimax-code) | `mcode` | 支持 `provider/model` 路线与图片附件；使用客户端配置的认证方式 |
| [ZCode](https://github.com/zai-org/ZCode) | `zcode` | 先在客户端选好模型；本项目不提供其模型覆盖参数；支持图片附件 |
| [Claude Code](https://code.claude.com/docs/en/cli-reference) | `claude` | 使用支持 `--safe-mode` 的兼容版本；图片通过原生消息块传入 |
| [Kimi Code](https://moonshotai.github.io/kimi-code/en/reference/kimi-command.html) | `kimi` | 文本支持新旧 Print 方式；识图需新版 ACP 通道，并先在客户端选模型、将模型调用 ID 留空 |
| [DeepSeek Harness](https://deepseek-harness.github.io/deepseek-harness/en/guide/quickstart) | `dsh` | 通过 ACP 调用；模型 ID 可填已配置的 `provider/model`，留空沿用 ACP profile；支持按确认尝试识图 |
| [OpenCode](https://dev.opencode.ai/v2/docs/cli/commands/) | `opencode` | 支持 `provider/model` 和图片附件；需具备本项目预检要求的私有运行参数 |
| [Qoder](https://docs.qoder.com/cli/run-in-scripts) | `qoder` | 建议显式选择模型 ID；`auto` 等档位不能当作底层模型身份；支持图片附件 |
| [WorkBuddy / CodeBuddy](https://www.workbuddy.cn/docs/cli/headless) | `codebuddy` | 使用 CodeBuddy CLI 协议；可识别受支持的桌面内置入口，桌面与独立 CLI 的账户配置需分别确认 |

CLI 发现与版本、参数预检不代表已验证登录、额度或实际模型能力。桌面应用已安装，也不一定带有可用 CLI；安装与认证要求以各 Harness 官方说明为准。

订阅权益或第三方 API 计费由所选 Harness 及提供商决定，galbench 不转换账户权益。需要传递额外凭据时，在客户端或启动服务前的环境变量中设置密钥；网页只填写**环境变量名**，不填写密钥值。

## 查看结果与复盘

测试完成后，在结算区查看三个榜单的成绩、总分、全对率及耗时，点击「查看错题」进入未满分题目的卡片页；「异常与人工补分」可处理调用和判分问题，亦可沿用原裁判仅补判失败题。

排行榜提供单榜与总分分类；点击模型查看历史，或打开「全部记录」按模型名、厂商和成绩筛选。「清除排名」开启新赛季，原始战绩仍可回看。

运行产物保存在本机 `runs/`，也可从界面导出：

| 文件 | 内容 |
| --- | --- |
| `manifest.json` | 题库哈希、模型与 Harness 配置、运行元数据 |
| `predictions.jsonl` | 逐题答卷、调用状态和耗时 |
| `scores.jsonl` / `scores.csv` | 逐题评分与异常信息 |
| `summary.json` / `report.md` | 成绩汇总与可读报告 |
| `runtime_events.jsonl` | 进度、重试、停止等运行事件 |

答题使用独立会话，仅传公开题面和必要图片；按 Harness 能力限制工具并审计轨迹。工具隔离能力因客户端而异，不能把 CLI 记录当作对服务端真实模型权重的认证。

## 不调用真实模型的检查

在项目根目录运行：

```shell
# 校验 900 题主集及其图片
python -m galbench validate

# 校验 10 道流程样题
python -m galbench validate spec/v2.0

# 使用本地模拟答题和裁判跑通三个榜单
python -m galbench demo
```

演示仅用于确认答题、判分和统计流程，结果不代表真实模型能力。题库使用 JSONL，主集位于 [data/dev-v2.0/](data/dev-v2.0/)，流程样题位于 [spec/v2.0/](spec/v2.0/)；各题包含来源记录与评分依据。
